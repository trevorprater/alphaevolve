# Security Policy

| Version | Supported          |
| ------- | ------------------ |

## Reporting a Vulnerability

If you discover a security vulnerability within AlphaEvolve, please send an email to security@alphaevolve.dev (or create a private security advisory on GitHub). All security vulnerabilities will be promptly addressed.

**Please do not report security vulnerabilities through public GitHub issues.**

### What to Include

When reporting a vulnerability, please include:

- Type of vulnerability (e.g., code injection, sandbox escape, credential exposure)
- Full paths of source file(s) related to the vulnerability
- Location of the affected source code (tag/branch/commit or direct URL)
- Step-by-step instructions to reproduce the issue
- Proof-of-concept or exploit code (if possible)
- Impact of the issue, including how an attacker might exploit it

## Security Best Practices

When using AlphaEvolve in production:

### 1. API Key Management
- **Never commit API keys** to version control
- Use environment variables or secure secret management systems
- Rotate API keys regularly
- Use separate keys for development, staging, and production

### 2. Sandbox Configuration
- **Always enable sandboxing** in production (`sandbox.enabled: true`)
- Use Docker-based sandboxing for maximum isolation
- Set appropriate resource limits (CPU, memory, timeout)
- Disable network access in sandbox (`sandbox.network_disabled: true`)
- Review and restrict `security.allowed_imports` to only necessary modules
- Keep `security.blocked_functions` comprehensive

### 3. Code Evaluation Security
- **Never evaluate untrusted code** without sandboxing
- Review LLM-generated code before production deployment
- Implement proper input validation in evaluation functions
- Use process isolation or Docker for evaluation
- Monitor resource usage during evaluation

### 4. Network Security
- Use HTTPS for all LLM API communications
- Implement rate limiting to prevent abuse
- Use firewall rules to restrict outbound connections
- Monitor for unusual API usage patterns

### 5. Dependency Security
- Regularly update dependencies
- Use `pip-audit` or similar tools to scan for vulnerabilities
- Pin dependency versions in production
- Review security advisories for dependencies

### 6. Logging and Monitoring
- Enable comprehensive logging
- Monitor for suspicious patterns (sandbox escapes, excessive API usage)
- Set up alerts for security events
- Regularly review logs for anomalies

### 7. Access Control
- Implement proper authentication for multi-user deployments
- Use principle of least privilege for service accounts
- Audit access to configuration files and databases

## Known Security Considerations

### LLM-Generated Code
AlphaEvolve executes code generated by Large Language Models. While we implement sandboxing and security controls, users should:
- Review evolved code before production deployment
- Implement additional validation layers for critical applications
- Test evolved code thoroughly in isolated environments
- Monitor for unexpected behavior

### Sandbox Limitations
No sandbox is 100% secure. Docker and process-based sandboxing provide strong isolation, but:
- Zero-day vulnerabilities in Docker/Linux may allow escapes
- Side-channel attacks may be possible
- Resource limits can be bypassed in some scenarios

**For critical production systems, implement defense in depth:**
- Run AlphaEvolve in isolated environments (VMs, containers)
- Use network segmentation
- Implement additional monitoring and logging
- Conduct regular security audits

### API Key Exposure
API keys provide access to potentially expensive LLM services:
- Use API key rotation policies
- Set up billing alerts with your LLM providers
- Implement rate limiting at the application level
- Monitor API usage for anomalies
